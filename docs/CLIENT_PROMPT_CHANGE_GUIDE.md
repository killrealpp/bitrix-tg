# Инструкция для клиента: как поменять промпты на сервере

Эта инструкция написана для человека без опыта работы с сервером. Идите по шагам сверху вниз и не пропускайте проверки.

## Что такое промпты

Промпты — это текстовые инструкции для ИИ, по которым он готовит отдельные посты для Telegram и MAX.

В проекте есть 8 основных слотов промптов: 4 тематики отдельно для Telegram и отдельно для MAX.

- Акции.
- Новости.
- События.
- Новинки товара.

Файл с промптами находится на сервере здесь:

```text
/opt/bitrix-tg/src/text/socialPrompts.ts
```

## Важное правило

Сейчас публикация во ВКонтакте выключена. Посты готовятся только для Telegram и MAX, у каждой площадки свой призыв к действию. ВК может оставаться только как дополнительная ссылка в блоке «Следите за нами».

Ссылка на текущий канал в этом блоке не нужна: читатель уже находится в нём. Поэтому в Telegram-посте оставляйте только ссылки на MAX и ВК, а в MAX-посте — только ссылки на Telegram и ВК. Ссылка для заказа и консультации сохраняется.

Для Telegram есть дополнительное автоматическое правило:

- если пост без фото, используется обычный Telegram-промпт с лимитом до 1200 символов;
- если пост с фото или альбомом, сервис сам добавляет к Telegram-промпту ограничение для caption: до 950 символов, включая призыв к действию, блок «Следите за нами» и хэштеги;
- при обрезке длинной подписи сервис старается сокращать основной текст, а не фиксированный блок ссылок.

Поэтому при ручной правке Telegram-промптов не нужно отдельно создавать второй блок “для фото” в файле. Достаточно сохранить обязательный CTA и блок «Следите за нами» в основном промпте, не добавляя в него ссылку на сам Telegram-канал.

## Шаг 1. Зайти на сервер

Откройте терминал и подключитесь к серверу:

```bash
ssh root@212.43.154.110
```

Если IP сервера другой, используйте актуальный IP.

После входа вы увидите строку примерно такого вида:

```text
root@n8n:~#
```

Это значит, что вы на сервере.

## Шаг 2. Перейти в папку проекта

Введите:

```bash
cd /opt/bitrix-tg
```

Что делает команда:

- `cd` означает “перейти в папку”.
- `/opt/bitrix-tg` — папка, где лежит проект.

Проверьте, что вы действительно в проекте:

```bash
pwd
```

Должно выйти:

```text
/opt/bitrix-tg
```

## Шаг 3. Посмотреть файлы проекта

Введите:

```bash
ls -la
```

Иногда на сервере работает короткая команда:

```bash
ll
```

Если `ll` не работает, используйте `ls -la`.

Вы должны увидеть файлы и папки проекта, например:

```text
package.json
src
tests
docs
dist
.env
```

Если таких файлов нет, значит вы не в той папке. Вернитесь к шагу 2.

## Шаг 4. Проверить, что проект сейчас работает

Введите:

```bash
curl https://poster.svarnoy-market.ru/health
```

Нормальный ответ:

```text
OK
```

Если ответ `OK`, сервис живой.

## Шаг 5. Открыть файл с промптами

Введите:

```bash
nano src/text/socialPrompts.ts
```

Что делает команда:

- `nano` — простой редактор текста прямо в терминале.
- `src/text/socialPrompts.ts` — файл, где лежат промпты.

После команды откроется текстовый редактор.

## Шаг 6. Найти нужный промпт

Внутри файла есть блоки:

```text
PROMPTS.telegram.promo
PROMPTS.telegram.company_news
PROMPTS.telegram.event
PROMPTS.telegram.product_new
PROMPTS.max.promo
PROMPTS.max.company_news
PROMPTS.max.event
PROMPTS.max.product_new
FORMAT_ONLY_PROMPT
```

Что за что отвечает:

- `PROMPTS.telegram.promo` и `PROMPTS.max.promo` — акции, скидки, распродажи.
- `PROMPTS.telegram.company_news` и `PROMPTS.max.company_news` — новости компании.
- `PROMPTS.telegram.event` и `PROMPTS.max.event` — события, выставки, мастер-классы.
- `PROMPTS.telegram.product_new` и `PROMPTS.max.product_new` — новинки товара.
- `FORMAT_ONLY_PROMPT` — прочие посты, если тип не распознан.

Чтобы найти блок в `nano`, нажмите:

```text
Ctrl + W
```

Введите название блока, например:

```text
telegram:
```

Нажмите `Enter`, затем внутри блока Telegram найдите нужную тематику, например `promo:`.

## Шаг 7. Изменить текст промпта

Промпт выглядит примерно так:

```ts
telegram: {
  promo: `
  Текст промпта здесь
  `.trim()
}
```

Менять нужно только текст внутри обратных кавычек нужной площадки и тематики:

```text
`
вот здесь
`
```

Не удаляйте:

```ts
promo: `
```

И не удаляйте строку в конце промпта:

```ts
`.trim()
```

Если случайно удалить эти строки, проект может не запуститься.

## Шаг 8. Сохранить файл

В `nano` нажмите:

```text
Ctrl + O
```

Это команда “сохранить”.

Появится строка с названием файла. Нажмите:

```text
Enter
```

Потом выйдите из редактора:

```text
Ctrl + X
```

Вы снова вернётесь в терминал.

## Шаг 9. Проверить, что файл изменился

Введите:

```bash
git status --short
```

Если файл изменён, вы увидите примерно:

```text
 M src/text/socialPrompts.ts
```

Это нормально. Буква `M` означает “modified”, то есть файл изменён.

## Шаг 10. Проверить проект перед перезапуском

Сначала установите зависимости, если вдруг они обновлялись:

```bash
npm install
```

Потом проверьте сборку:

```bash
npm run build
```

Если всё хорошо, в конце не будет ошибок, и команда просто завершится.

Если появилась ошибка красным текстом, не перезапускайте сервис. Нужно вернуть файл или исправить ошибку.

## Шаг 11. Перезапустить сервис

Введите:

```bash
sudo systemctl restart bitrix-tg
```

Что делает команда:

- `sudo` — выполнить команду с правами администратора.
- `systemctl restart` — перезапустить сервис.
- `bitrix-tg` — название нашего сервиса.

После этой команды проект начнёт работать уже с новым промптом.

## Шаг 12. Проверить, что сервис запустился

Введите:

```bash
curl https://poster.svarnoy-market.ru/health
```

Должно быть:

```text
OK
```

Потом проверьте статус сервиса:

```bash
sudo systemctl status bitrix-tg --no-pager
```

Нормально, если видите:

```text
active (running)
```

Чтобы выйти из просмотра статуса, если он открылся не сразу в обычном режиме, нажмите:

```text
q
```

## Шаг 13. Посмотреть последние логи

Введите:

```bash
journalctl -u bitrix-tg -n 80 --no-pager
```

Что делает команда:

- `journalctl` показывает логи.
- `-u bitrix-tg` показывает логи только нашего сервиса.
- `-n 80` показывает последние 80 строк.
- `--no-pager` выводит всё сразу.

Если сервис работает, там не должно быть постоянных ошибок запуска.

## Шаг 14. Проверить на реальном посте

После изменения промпта создайте или обновите тестовый элемент в Bitrix.

Проверьте:

- пост появился в Telegram или MAX;
- текст соответствует новому промпту;
- ВК не выбран как основной призыв к действию;
- ссылки отображаются нормально.

В логах полезная строка:

```text
AI social text preparation completed
```

Она означает, что ИИ подготовил текст поста.

## Если промпты уже изменили в Git

Если разработчик уже поменял промпты, сделал `git push`, а вам нужно только обновить сервер, используйте короткий сценарий:

```bash
cd /opt/bitrix-tg
git pull
npm install
npm run build
sudo systemctl restart bitrix-tg
curl https://poster.svarnoy-market.ru/health
journalctl -u bitrix-tg -n 80 --no-pager
```

Что здесь происходит:

- `cd /opt/bitrix-tg` — переходим в проект.
- `git pull` — забираем свежие изменения с промптами.
- `npm install` — проверяем зависимости.
- `npm run build` — собираем проект.
- `sudo systemctl restart bitrix-tg` — перезапускаем сервис.
- `curl .../health` — проверяем, что сервис отвечает.
- `journalctl ...` — смотрим последние логи.

После этого сервер работает с новыми промптами.

## Если нужно сохранить ручные изменения в Git

Если вы меняли файл прямо на сервере и хотите сохранить эти изменения в Git, выполните:

```bash
git status --short
git add src/text/socialPrompts.ts
git commit -m "Update social prompts"
git push
```

Что это значит:

- `git status --short` — показать изменённые файлы.
- `git add src/text/socialPrompts.ts` — подготовить файл с промптами к сохранению.
- `git commit -m "Update social prompts"` — сохранить изменение в истории проекта.
- `git push` — отправить изменение в удалённый Git-репозиторий.

Если `git push` просит логин, пароль или токен, лучше остановиться и обратиться к разработчику.

## Если что-то пошло не так

### Health-check не отвечает OK

Проверьте статус:

```bash
sudo systemctl status bitrix-tg --no-pager
```

Проверьте логи:

```bash
journalctl -u bitrix-tg -n 120 --no-pager
```

### Ошибка после npm run build

Скорее всего, случайно удалили кавычку, обратную кавычку или `.trim();`.

Откройте файл снова:

```bash
nano src/text/socialPrompts.ts
```

Проверьте, что каждый промпт начинается примерно так:

```ts
promo: `
```

И заканчивается примерно так:

```ts
`.trim()
```

### Нужно посмотреть, что именно изменили

Введите:

```bash
git diff src/text/socialPrompts.ts
```

Эта команда покажет изменения в файле.

### Нужно отменить ручные изменения

Используйте эту команду только если точно хотите вернуть файл к версии из Git:

```bash
git restore src/text/socialPrompts.ts
```

После отмены снова выполните:

```bash
npm run build
sudo systemctl restart bitrix-tg
curl https://poster.svarnoy-market.ru/health
```
