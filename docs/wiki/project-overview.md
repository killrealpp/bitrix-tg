# Обзор проекта

Проект "Постер Битрикс" должен заменить n8n workflow самостоятельным сервисом. Сервис принимает JSON от вебхука Битрикс, решает, нужно ли публиковать элемент, готовит текст под ограничения Telegram, публикует пост в Telegram и сохраняет связь между `element_id` Битрикс и `message_id` Telegram.

Главная ценность для пользователя: контент-менеджер работает в Битрикс как обычно, а Telegram-канал автоматически получает новые и обновленные публикации. Если запись в Битрикс неактивна или не помечена для соцсетей, сервис ничего не публикует.

## Что входит в проект

Сервис должен поддерживать:

- прием вебхука с массивом событий;
- фильтрацию по `active` и `pub_news_social`;
- нормализацию фото из `PHOTOS`, где значение может быть `null`, объектом или массивом;
- создание новой Telegram-публикации без фото, с одним фото или с несколькими фото;
- редактирование уже опубликованной Telegram-публикации при повторном приходе того же `element_id`;
- публикацию не сразу, а в момент из поля "начало активности";
- хранение состояния публикации в базе данных;
- идемпотентность, чтобы повторный одинаковый вебхук не создавал дубли.

## Что пока не определено

ТЗ пока не фиксирует точный стек, тип базы данных, формат текста, целевой Telegram-чат, точное имя поля "начало активности" и политику удаления/перепубликации при сложном изменении медиа. Эти вопросы собраны в [[open-questions]].
