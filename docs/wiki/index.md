# Индекс проекта "Постер Битрикс"

Эта wiki фиксирует ТЗ для сервиса, который принимает вебхук из Битрикс, проверяет условия публикации, приводит данные к нормальной форме, публикует или редактирует посты в Telegram, публикует/удаляет посты в VK и MAX, и хранит связь между элементом Битрикс и внешними публикациями.

Wiki устроена по паттерну из `obsidian.txt`: страницы маленькие, связаны между собой, а `index.md` помогает быстро найти нужную часть проекта.

## Основные страницы

- [[project-overview]] - цель проекта, границы и пользовательский результат.
- [[input-webhook-contract]] - структура входящего JSON и правила нормализации.
- [[business-rules]] - детальные сценарии новых публикаций и редактирования.
- [[data-model]] - предлагаемая модель базы данных и почему одной строки недостаточно для альбомов.
- [[sqlite-local-db]] - основной автономный вариант хранения через локальную SQLite-базу.
- [[n8n-db-gateway]] - временный доступ к Postgres через n8n webhook, пока база живет только внутри docker-compose с n8n.
- [[telegram-publishing]] - правила работы с Telegram Bot API, сообщениями, фото и альбомами.
- [[ai-text-fitting]] - как использовать OpenRouter для SMM-подготовки выбранных типов постов и последующей подгонки в лимиты.
- [[scheduled-publishing]] - публикация по полю "начало активности".
- [[open-questions]] - вопросы, которые нужно подтвердить перед реализацией.
- [[graph]] - Mermaid-граф страниц, сущностей и сценариев.
- [[log]] - хронологический журнал изменений wiki.

## Как читать

Для общего понимания начните с [[project-overview]], затем перейдите в [[business-rules]]. Если задача - реализация, откройте корневой файл `POSTER_BITRIX_EXECPLAN.md`: он написан как самодостаточный план работ по формату `PLANS.md`.
