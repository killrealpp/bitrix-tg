# Подготовка и подгонка текста через ИИ

2026-07-01 / multi-social release: ИИ используется в двух режимах. Для типов
`event`, `promo`, `company_news` и `product_new` он адаптирует исходные данные
под SMM-промпт магазина "СВАРНОЙ" и возвращает готовый пост до 1200 символов. Для
`entertainment`, `unknown` и любых прочих типов он вызывает отдельный
format-only промпт: не переписывает смысл, а только аккуратно оформляет текст,
добавляет 2-4 уместных эмодзи и сохраняет исходные факты.

После подготовки все платформенные лимиты все равно проверяются. Если OpenRouter
недоступен, вернул пусто или слишком длинно, публикация не блокируется:
сервис применяет deterministic truncation.

## Когда вызывается ИИ

Для всех типов сервис вызывает `aiPrepare` после сборки текста из Bitrix-полей
и до platform-fit, если AI provider настроен. Разница только в промпте:
business-типы получают SMM-адаптацию, а `entertainment`/`unknown` получают
format-only оформление без смыслового переписывания.

Затем сервис проверяет платформенные лимиты:

- обычное Telegram-сообщение: hard limit `4096`, target `3900`;
- caption у фото или альбома: hard limit `1024`, target `950`.
- MAX text: hard limit `4000`, target `3800`;
- VK: используется консервативный внутренний fit, но SMM-подготовка уже целится
  в 1200 символов.

Если итоговый текст не помещается в hard limit, сервис применяет deterministic
truncation по границе предложения/слова и продолжает публикацию.

## OpenRouter

Production text fitting использует OpenRouter Chat Completions:

- endpoint: `https://openrouter.ai/api/v1/chat/completions`;
- auth: `Authorization: Bearer <OPENROUTER_API_KEY>`;
- model из `OPENROUTER_MODEL`, например `openai/gpt-4.1-mini`;
- optional attribution headers: `HTTP-Referer` и `X-OpenRouter-Title`.

Env:

```env
OPENROUTER_API_KEY=
OPENROUTER_MODEL=openai/gpt-4.1-mini
OPENROUTER_API_BASE_URL=https://openrouter.ai/api/v1
OPENROUTER_SITE_URL=https://svarnoy-market.ru
OPENROUTER_APP_TITLE=bitrix-tg
OPENROUTER_TIMEOUT_MS=20000
```

Для обратной совместимости `OPENAI_API_KEY` и `OPENAI_MODEL` остаются fallback-алиасами. Если `OPENROUTER_API_KEY` пустой, сервис использует `OPENAI_API_KEY`; модель вида `gpt-4.1-mini` автоматически превращается в OpenRouter-compatible `openai/gpt-4.1-mini`.

## Правила поведения ИИ

ИИ должен:

- сохранять факты, даты, названия, цены, адреса, ссылки и product names;
- не добавлять новых фактов, хэштегов, приветствий или объяснений;
- сохранять исходный язык и нейтральный тон;
- возвращать только финальный текст без объяснений;
- для `event`, `promo`, `company_news`, `product_new` соблюдать
  соответствующий SMM-промпт и ограничение около 1200 символов;
- для `entertainment`, `unknown` и прочих типов только оформлять текст:
  переносы, легкая структура, 2-4 эмодзи, без новых фактов, цен, сроков,
  адресов, призывов к покупке и хэштегов.

## Клиентские правила оформления

Для Telegram в блоке «Следите за нами» остаются ссылки только на MAX и ВК; для
MAX — только на Telegram и ВК. Ссылка на площадку, где уже опубликован пост,
не добавляется.

У типа `event` вместо стандартного призыва для заказа используется обязательное
окончание: «Если остались вопросы по событию, мы на связи. Будем рады ответить
на ваши вопросы.» Затем добавляется ссылка на диалог в текущей платформе и блок
«Следите за нами» с двумя внешними сетями. Сервис дописывает это окончание после
ответа ИИ, поэтому оно есть и в MAX-постах, даже если модель пропустила блок в
своём тексте. Для запланированных событий правило повторно применяется перед
фактической публикацией.

Для всех типов, кроме `promo`, ИИ использует 4-7 смысловых эмодзи для заголовков
и подзаголовков и ставит отдельный эмодзи или маркер перед каждым пунктом
характеристик, преимуществ, условий, маршрутов и других перечислений. Эмодзи не
должны дублироваться в одной строке ради украшения.

Смысловые абзацы и подзаголовки отделяются пустой строкой; технический символ
обратного слэша не используется как перенос строки. Нельзя писать общие фразы
вроде «это важно для клиентов»: пост должен прямо называть практическую пользу,
маршрут, условие или действие для читателя.

## Надежность

OpenRouter token и legacy `OPENAI_API_KEY` считаются секретами и проходят redaction в ошибках и логах. Сбой ИИ не должен блокировать публикацию: в худшем случае пост публикуется с deterministic truncation.
