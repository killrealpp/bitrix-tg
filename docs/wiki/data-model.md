# Модель данных

В исходном описании названа таблица с полями `bitrix_id`, `tg_message_id` и `chat_id`. Этого достаточно только для самого простого случая: один элемент Битрикс равен одному сообщению Telegram.

Для альбомов, добавления фото к старому текстовому посту и хранения нескольких сообщений нужна модель из двух уровней: одна запись поста Битрикс и несколько связанных Telegram-сообщений.

## Таблица `bitrix_posts`

Назначение: хранить состояние одного элемента Битрикс.

Рекомендуемые поля:

- `id` - внутренний первичный ключ;
- `bitrix_id` - уникальный идентификатор из `element_id`;
- `status` - состояние: `ignored`, `scheduled`, `publishing`, `published`, `failed`;
- `chat_id` - целевой Telegram-чат или канал;
- `main_message_id` - главное сообщение Telegram, если оно есть;
- `publication_kind` - `text`, `photo`, `media_group` или `mixed`;
- `scheduled_at` - время публикации из поля "начало активности";
- `source_text` - исходный собранный текст из Битрикс до подгонки;
- `telegram_text` - финальный текст или caption, отправленный в Telegram;
- `photos_json` - нормализованный массив фото;
- `payload_hash` - хэш нормализованного состояния для защиты от дублей;
- `last_error` - последняя ошибка публикации или редактирования;
- `scheduled_retry_count` - сколько автоматических retry уже было сделано для scheduled-публикации;
- `admin_notified_at` - когда сервис уведомил администратора после повторной scheduled-ошибки;
- `created_at` и `updated_at` - технические даты.

`main_message_id` сохраняет совместимость с простыми сценариями, но не заменяет список сообщений.

## Таблица `telegram_messages`

Назначение: хранить каждое сообщение Telegram, созданное для одного поста Битрикс.

Рекомендуемые поля:

- `id` - внутренний первичный ключ;
- `post_id` - ссылка на `bitrix_posts.id`;
- `chat_id` - Telegram-чат;
- `tg_message_id` - идентификатор сообщения Telegram;
- `role` - роль сообщения: `text`, `photo`, `album_item`, `extra_photo`;
- `media_index` - порядок фото в альбоме или `null` для текста;
- `media_url` - URL фото из Битрикс;
- `telegram_file_id` - `file_id` Telegram, если сервис решил его сохранять;
- `created_at` и `updated_at` - технические даты.

Уникальность полезно задавать по паре `chat_id` и `tg_message_id`.

## Почему не одна таблица

Одна таблица ломается в трех сценариях:

- несколько фото создают несколько `message_id`;
- к старому текстовому сообщению нельзя "прикрепить" фото, нужно отправить дополнительное сообщение;
- при редактировании альбома нужно знать `message_id` каждого элемента, а не только первого.
